# 深空滑翔器 · 离线复核封存链

失联窗口内，姿态事件在随设备携行的离线复核页上暂存并封存；返航后审查员重开页面，
即可确认浏览器在封存中断后不会遗漏、重排或混入半写入批次。

## 架构

```
core/       共享封存引擎（浏览器与 Node 测试同一份代码）
  canonical.js        规范 UTF-8 编码 + SHA-256（WebCrypto）
  validate.js         批次规则：稳定批次标识、至多 24 条、序号严格递增、文本载荷
  engine.js           封存协议、幂等/冲突处理、并发收敛、恢复扫描
  memory-storage.js   内存存储适配器（故障演练与规则测试用）
frontend/   离线复核页（IndexedDB 适配器 + UI，esbuild 打包）
web/        静态页服务器 + GET /health（无依赖，PORT 可配）
verify/     一次运行后退出的检验服务：规则测试、中断恢复演练、双连接并发验收、前端构建、HTTP 冒烟
compose.yaml
```

## 封存协议

**规范编码与哈希链**：段摘要对以下规范化文本的 UTF-8 字节计算 SHA-256——
首行为前段摘要（创世段为 64 个 `0`），随后每行一条事件 `序号|载荷`。
新段由此以前段摘要绑定成链；批次内容哈希（不含前驱行）用于判定"同内容"。

**持久化顺序**（IndexedDB，每步独立事务提交）：

1. **准备意图**（`prepares`，键为批次标识）：内容哈希、事件、前驱摘要、期望段摘要
2. **不可变段**（`segments`，键为自身摘要，内容寻址）：事件、序号范围、前驱、回执
3. **活动清单**（`manifest`，单条 active）：有序段摘要列表、批次→段映射、链头

只有**清单指向**且**摘要、前驱、序号连续**的段才属于已封存记录。

**并发收敛**：清单切换是对"读取时版本"的原子比较并交换（CAS），同一设备上两个页面
交错提交时，只有一个能基于同一快照切换成功；失败方重读清单、把意图改挂到新链头后
重试，因此两份合法批次必然收敛为唯一、连续的顺序链——每个批次只出现一次，后续段的
回执绑定实际前驱。若某批次已无法接续当前链（序号回退），该次提交返回拒绝而非已封存。

**幂等与冲突**：同标识同内容重传返回原回执、不追加（跨连接并发重传同样收敛到首次
最终回执）；同标识不同内容保留既有证据（链与段不动），返回并记录明确冲突。新批次
首条序号必须大于已封存末条序号。

## 中断恢复

故障演练可在**准备意图写入后 / 段写入后 / 清单切换后**注入中断。下一次打开时：

- 扫描并校验残留状态；清单链截断到最长有效前缀，记录首个阻断证据；
- 无对应段的准备意图 → 丢弃，不得入链；
- 损坏的准备段 → 拒绝入链（保留阻断证据，可干净重传）；
- 完整但未发布的同批次 → 只能按既定意图（期望摘要寻址）恢复为唯一结果；
- 已发布段 → 清理已完成意图，绝不重复追加；
- 意图前驱与当前链头不符 → 阻断，不得强行链接。

页面展示每段的**序号范围、前驱摘要、恢复动作**以及**首个阻断证据**，
另有冲突记录面板与交互式故障演练入口。

## 运行

```bash
# 构建并运行全部检验（规则、恢复演练、前端构建、HTTP 冒烟），退出码即结果
docker compose up --build --abort-on-container-exit --exit-code-from verify

# 仅起页面（宿主端口可配置，默认 8080）
HOST_PORT=9000 docker compose up --build web
# 页面: http://localhost:9000/   健康: http://localhost:9000/health
```

本地开发（无需 Docker）：

```bash
cd frontend && npm ci && node build.js --out ../web/public   # 前端构建
node web/server.js                                            # 页面服务 :8080
WEB_URL=http://127.0.0.1:8080 node verify/run.js              # 完整检验，退出码报告
```

## 页面使用

- **提交批次**：批次标识 + 每行一条 `序号|文本载荷`（序号严格递增，至多 24 条）。
- **故障演练**：选择中断点执行，引擎在该阶段持久化后模拟崩溃，随即关闭并重开
  IndexedDB 连接执行恢复；也可随时点击"重开页面"触发真实恢复。
